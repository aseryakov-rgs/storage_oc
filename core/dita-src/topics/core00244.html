Самостоятельное формирование дескрипторов и выдача ключей

Чтобы построить универсальную систему прав доступа вы можете самостоятельно формировать дескрипторы доступа, ключи и выдавать ключи пользователям. В этом случае можно контролировать права как на уровне элементов проекта, так и на уровне отдельных элементов данных (RLS).

Примечание: В приложении этот вариант может совмещаться с простым вариантом, использующим автоматическую выдачу прав (подробнее).

Классы ключей доступа, добавленные разработчиком

Вы можете добавлять в проект собственные классы ключей доступа. Для этого предназначены элементы проекта вида КлассКлючейДоступа. Элементу проекта этого вида вы можете добавить параметры. Для каждого сочетания значений этих параметров «1С:Кабинет сотрудника» будет создавать свой уникальный ключ. Подробнее о классах ключей доступа читайте здесь.

Построение собственной системы прав

В собственной системе прав можно контролировать права как на уровне элементов проекта, так и на уровне отдельных элементов данных (RLS). Например, если чтение справочника разрешено, то дальше проверяется право на чтение конкретного элемента справочника. Если оно есть — значит можно читать этот элемент. Если чтение запрещено — значит этот элемент справочника читать нельзя. Если же чтение всего справочника запрещено, то права на отдельные его элементы не проверяются и чтение любого элемента запрещается.

Для реализации такой системы прав вам потребуется вручную создавать дескрипторы доступа, ключи и устанавливать соответствие пользователей и ключей.

Управление доступом в проекте

Каждый вид элементов проекта, для которого поддерживается управление доступом, имеет фиксированный набор прав, предоставляемый платформой. Например, Справочник имеет права Создание, Чтение, Изменение, Удаление.

Каждый элемент проекта этих видов содержит свойство КонтрольДоступа. В этом свойстве вы можете перечислить, каким образом будет контролироваться доступ к тому или иному праву, например:

Чтобы получить возможность вручную создавать дескрипторы для того права (тех прав), которые вы хотите контролировать самостоятельно, выберите способ контроля доступа РазрешенияВычисляются или РазрешенияВычисляютсяДляКаждогоОбъекта. Например:

КонтрольДоступа: 
    Создание: РазрешеноАутентифицированным
    Чтение: РазрешенияВычисляются
    ПоУмолчанию: РазрешеноАдминистраторам
Эти два способа контроля доступа отличаются следующим:
  • РазрешенияВычисляются позволит вам контролировать права только на уровне всего элемента проекта;
  • РазрешенияВычисляютсяДляКаждогоОбъекта позволит вам контролировать права и на уровне всего элемента проекта и на уровне отдельных его элементов (RLS).

Вычисление дескрипторов доступа

Для того чтобы вы могли создать дескрипторы доступа, у типов встроенного языка, порождаемых элементом проекта, есть события ВычислитьДескрипторыДоступа и ВычислитьДескрипторыДоступаДляОбъектов. Эти события нужно обрабатывать в модулях этих типов, например, в модуле справочника, в модуле Http-сервиса, в модуле регистра сведений.

Предположим, что вы добавили в приложение собственный класс ключей доступа с именем КлючиГруппСотрудников. Этот класс имеет один параметр Группа, типа перечисление ГруппыСотрудников. Это перечисление вы тоже добавили сами и оно имеет два элемента: Менеджеры и Руководители. Таким образом вы сможете иметь два ключа этого класса, с помощью которых вы разделите всех пользователей на две группы.

Событие ВычислитьДескрипторыДоступа предназначено для создания дескрипторов доступа для всего элемента проекта в целом. Оно может выглядеть, например, следующим образом:

метод ВычислитьДескрипторыДоступа() : Массив<ДескрипторДоступа>

    пер Дескрипторы: Массив<ДескрипторДоступа>   // массив для возврата декскрипторов

    // Получить ключи доступа
    пер КлючМенеджеров = новый КлючиГруппСотрудников.Объект(ГруппыСотрудников.Менеджеры)
    пер КлючРуководителей = новый КлючиГруппСотрудников.Объект(ГруппыСотрудников.Руководители)

    // Создать дескриптор доступа
    Дескрипторы.Добавить(новый ДескрипторДоступа([КлючМенеджеров, КлючРуководителей], [СправочникПраво.Чтение]))

    возврат Дескрипторы
;

Здесь чтение справочника в целом разрешается всем пользователям: и тем, кто имеет ключ руководителей, и тем, кто имеет ключ менеджеров.

Событие ВычислитьДескрипторыДоступаДляОбъектов предназначено для создания дескрипторов доступа для отдельного элемента справочника. Оно может выглядеть, например, следующим образом:

метод ВычислитьДескрипторыДоступаДляОбъектов(Элементы: ЧитаемыйМассив<Поставщики.Объект>) : ЧитаемоеСоответствие<Поставщики.Объект, Массив<ДескрипторДоступа>>

    пер Результат = <Поставщики.Объект, Массив<ДескрипторДоступа>>{:}   // соответствие для возврата

    // Получить ключи доступа
    пер КлючМенеджеров = новый КлючиГруппСотрудников.Объект(ГруппыСотрудников.Менеджеры)
    пер КлючРуководителей = новый КлючиГруппСотрудников.Объект(ГруппыСотрудников.Руководители)
 
    для Элемент из Элементы
        пер Дескрипторы = <ДескрипторДоступа>[]   // массив для возврата дескрипторов

        /* Проанализировать свойства элемента справочника, в зависимости от чего 
           либо разрешить менеджерам его чтение, либо нет */
        если Элемент.ВажноеСвойство
            Дескрипторы.Добавить(новый ДескрипторДоступа([КлючРуководителей], [СправочникПраво.Чтение]))
        иначе
            Дескрипторы.Добавить(новый ДескрипторДоступа([КлючМенеджеров, КлючРуководителей], [СправочникПраво.Чтение]))
        ;
        Результат.Вставить(Элемент, Дескрипторы)
    ;
    возврат Результат
;

Здесь, если элемент справочника имеет ВажноеСвойство == Истина, то чтение этого элемента разрешается только тем, кто имеет ключ руководителей. В противном случае элемент справочника могут читать и те, кто имеет ключ руководителей, и те, кто имеет ключ менеджеров.

В каких случаях какие обработчики вам следует иметь? Это зависит от того, какой способ контроля доступа вы выбрали в элементе проекта:

  • если вы выбрали РазрешенияВычисляются, то вы должны иметь только обработчик события ВычислитьДескрипторыДоступа;

  • если вы выбрали РазрешенияВычисляютсяДляКаждогоОбъекта, то вы должны иметь обработчики обоих событий.

После того, как вы добавили, например, в проект новый справочник, нужно запустить приложение и записать для этого справочника дескрипторы доступа.

Но событие ВычислитьДескрипторыДоступа не вызывается автоматически. Для его вызова используйте метод ПересчитатьДескрипторыДоступа() (например, для справочника: <ИмяСправочника>.ПересчитатьДескрипторыДоступа()). Такой вызов можно разместить в обработчике ПриОбновлении.

Событие ВычислитьДескрипторыДоступаДляОбъектов вызывается автоматически при записи элемента справочника. Таким образом, после добавления справочника и записи его элементов в приложении будут нужные дескрипторы как для самого справочника в целом, так и для его элементов.

Примечание: Событие ВычислитьДескрипторыДоступаДляОбъектов также вызывается в результате вызова метода ПересчитатьДескрипторыДоступаДляОбъектов(). Поскольку этот метод позволяет пересчитать дескрипторы сразу для нескольких или для всех объектов, первый параметр в обработчике ВычислитьДескрипторыДоступаДляОбъектов является массивом объектов.

Выдача ключей доступа

К этому же моменту (после добавления справочника и записи его элементов) в системной таблице ключей пользователя тоже будут все необходимые записи. Это происходит потому, что данные в эту таблицу добавляются в момент первого получения ключей, которое выполнялось в обработчике события ВычислитьДескрипторыДоступа. Вспомните:

...
    // Получить ключи доступа
    пер КлючМенеджеров = новый КлючиГруппСотрудников.Объект(ГруппыСотрудников.Менеджеры)
    пер КлючРуководителей = новый КлючиГруппСотрудников.Объект(ГруппыСотрудников.Руководители)
...

В этот момент у менеджера этого класса ключей вызывается событие ПроверитьНаличиеКлючейДоступа, в обработчике которого вы и формируете соответствие этого ключа пользователям. Например:

метод ПроверитьНаличиеКлючейДоступа(Ключи: ЧитаемыйМассив<КлючиГруппСотрудников.Объект>, ПользователиДляПроверки: ЧитаемыйМассив<Пользователи.Объект>): Соответствие<КлючиГруппСотрудников.Объект, Массив<Пользователи.Ссылка>>

    знч Результат = <КлючиГруппСотрудников.Объект, Массив<Пользователи.Ссылка>>{:}
    
    для Ключ из Ключи
        знч ПользователиКлюча = <Пользователи.Ссылка>[]
        для Пользователь из ПользователиДляПроверки
 
            // Анализировать либо свойства пользователя, либо дополнительную информацию о нем
            // в результате чего относим его либо к менеджерам (ЭтоМенеджер == Истина), либо к руководителям (ЭтоМенеджер == Ложь)
            пер ЭтоМенеджер: Булево

            // Если пользователь – менеджер и ключ менеджера – добавить пользователю этот ключ
            если ЭтоМенеджер и Ключ.Группа == ГруппыСотрудников.Менеджеры
                ПользователиКлюча.Добавить(Пользователь.Ссылка)
            ;
 
            // Если пользователь – руководитель и ключ руководителя – добавить пользователю этот ключ
            если не ЭтоМенеджер и Ключ.Группа == ГруппыСотрудников.Руководители
                ПользователиКлюча.Добавить(Пользователь.Ссылка)
            ;
        ;
        Результат.Вставить(Ключ, ПользователиКлюча)
    ;
    возврат Результат
;
Ключ передается в этот обработчик как элемент массива потому, что событие ПроверитьНаличиеКлючейДоступа платформа вызывает в следующих случаях:
  • При получении ключа доступа по набору параметров во встроенном языке: новый <ИмяКлассаКлючейДоступа>.Объект() — в этом случае в обработчик передается объект ключа и все подключенные пользователи;
  • При подключении нового пользователя к приложению — в этом случае обработчик вызывается у каждого класса ключей доступа, которые есть в проекте, и в него передаются все ключи конкретного класса и подключившийся пользователь.
