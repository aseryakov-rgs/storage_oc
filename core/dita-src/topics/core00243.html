Автоматическая выдача прав

В простейшем случае «1С:Кабинет сотрудника» создает систему прав, которая не требует программирования. Права контролируются на уровне элементов проекта для нескольких предопределенных категорий пользователей.

Примечание: В приложении этот вариант может совмещаться с более сложным вариантом, использующим самостоятельное формирование дескрипторов и выдачу ключей (подробнее).

Предопределенные классы ключей доступа

В «1С:Кабинете сотрудника» существует три предопределенных класса ключей доступа, каждый из которых имеет единственный ключ:

  • КлючДоступаДляВсех — этот ключ «1С:Кабинет сотрудника» автоматически выдает всем пользователям, в том числе анонимным;
    Примечание: Коротко о том, кто такой анонимный пользователь. Интерфейсные компоненты:
    • СтандартноеКлиентскоеПриложениеСРазделами и
    • ПроизвольноеКлиентскоеПриложение
    имеют свойство РежимАутентификации. Стандартно это свойство имеет значение Аутентифицированный, но вы можете установить его в значение НеАутентифицированный и тогда пользователь не будет перенаправлен на страницу аутентификации при входе в приложение, то есть будет анонимным. Такого пользователя не будет в списке подключенных пользователей и Пользователи.ТекущийПользователь будет возвращать Неопределено.
  • КлючДоступаДляАутентифицированных — этот ключ «1С:Кабинет сотрудника» автоматически выдает всем пользователям приложения кроме анонимных;
  • КлючДоступаАдминистратора — этот ключ «1С:Кабинет сотрудника» автоматически выдает всем пользователям приложения, являющимся его администраторами (свойство подключенного пользователя Пользователи.Объект.Администратор)
Перечисленные ключи «1С:Кабинет сотрудника» использует самостоятельно, об этом будет рассказано далее.

Кроме перечисленных ключей в «1С:Кабинете сотрудника» существует еще один предопределенный класс ключей доступа КлючДоступаПользователя. Этот класс имеет параметр Пользователь. Благодаря этому параметру класс имеет столько ключей (экземпляров класса), сколько существует подключенных пользователей. «1С:Кабинет сотрудника» поддерживает уникальность ключей по набору значений их параметров и, значит, для каждого пользователя она будет создавать свой уникальный ключ. Например, ключ для текущего пользователя:

пер Ключ = новый КлючДоступаПользователя.Объект(Пользователи.ТекущийПользователь)

В отличие от перечисленных выше трех классов ключей, ключи класса КлючДоступаПользователя «1С:Кабинет сотрудника» самостоятельно только выдает пользователям, но никак не связывает с элементами проекта (не создает дескрипторы доступа). Вы можете самостоятельно создать дескрипторы, если ваша система прав построена таким образом, что конкретное право нужно ставить в соответствие конкретному пользователю, без промежуточных понятий типа «роль» и т. п. (подробнее).

Построение автоматической системы прав

В автоматической системе прав права контролируются на уровне элементов проекта. Например, если чтение справочника разрешено — значит можно читать все его элементы. Если чтение справочника запрещено — ни один из элементов справочника прочитать нельзя.

Управление доступом в проекте

Каждый вид элементов проекта, для которого поддерживается управление доступом, имеет фиксированный набор прав, предоставляемый «1С:Кабинетом сотрудника». Например, Справочник имеет права Создание, Чтение, Изменение, Удаление.

Каждый элемент таких видов имеет свойство КонтрольДоступа. В этом свойстве вы можете перечислить, каким образом будет контролироваться доступ к тому или иному праву, например:

КонтрольДоступа: 
    Создание: РазрешеноАутентифицированным
    Чтение: РазрешеноВсем
    ПоУмолчанию: РазрешеноАдминистраторам

ПоУмолчанию — это специальное обозначение, которое подразумевает все права, не перечисленные явно.

РазрешеноАутентифицированным, РазрешеноВсем и РазрешеноАдминистраторам — это способы контроля доступа, использующие предопределенные ключи:
  • РазрешеноАутентифицированным использует КлючДоступаДляАутентифицированных;
  • РазрешеноВсем использует КлючДоступаДляВсех;
  • РазрешеноАдминистраторам использует КлючДоступаАдминистратора.

Вычисление дескрипторов и выдача ключей

Благодаря такому описанию элемента проекта «1С:Кабинет сотрудника» автоматически запишет для него дескрипторы доступа со следующими ключами:

<Создание: КлючДоступаДляАутентифицированных>
<Чтение: КлючДоступаДляВсех>
<Изменение, Удаление: КлючДоступаАдминистратора>

При создании этих ключей доступа «1С:Кабинет сотрудника» сразу же заполнит системную таблицу ключей пользователя, т. к. в предопределенном элементе проекта Пользователи есть вся информация для привязки того или иного ключа к пользователю (подробнее).

В дальнейшем эта система прав доступа будет поддерживаться следующим образом:
  • При подключении к приложению нового пользователя «1С:Кабинет сотрудника» автоматически запишет для него нужный ему предопределенный ключ;
  • При изменении существующего пользователя (например, обычному пользователю включили признак того, что он является администратором) «1С:Кабинет сотрудника» также автоматически (при записи пользователя) обновит ключ с КлючДоступаДляВсех на КлючДоступаАдминистратора.
